# Руководства по эксплуатации «Мониторинга сигналов» — исходники

Три страницы (главный администратор, администратор и руководитель, подрядчик)
собираются из Python-шаблонов: общий каркас, стили и скрипт лежат отдельно,
тексты и подбор скриншотов — по одному файлу на роль. Скриншоты встраиваются
в HTML как base64 (WebP), поэтому каждая страница — один самодостаточный файл.

## Структура

```
guides-source/
├── build.py                 каркас страницы и компоненты (shot, scenario, table, matrix, fsm, clock…)
├── style.css                токены (светлая/темная тема, цвет роли), компоненты, анимации
├── script.js                тема, появление при прокрутке, оглавление, лайтбокс, сценарии, живая карточка
├── content_superadmin.py    текст и структура руководства главного администратора
├── content_admin.py         … администратора и руководителя
├── content_contractor.py    … подрядчика
├── links.json               ссылки на опубликованные страницы (взаимные ссылки в подвале)
├── build_all.py             собрать все три
├── shots/                   скриншоты (WebP), снятые с демо-базы
├── out/                     результат: тело страницы для публикации как Artifact
├── dist/                    результат: автономные HTML с полным каркасом
└── tools/
    ├── seed.mjs             наполнить чистую базу демо-данными через API
    ├── backdate.py          сдвинуть метки времени, чтобы возраст сигналов был правдоподобным
    ├── shoot.mjs            снять все экраны под каждой ролью (Playwright)
    ├── webp.py              PNG → WebP
    ├── seed-ids.json        идентификаторы сигналов демо-базы (пишет seed.mjs)
    └── fixtures/            файлы-вложения для демо-сигналов
```

## Пересобрать страницы (тексты или стили изменились)

```bash
python3 build_all.py
# → out/guide-*.html   — для публикации как Artifact
# → dist/guide-*.html  — открыть в браузере / положить в docs/guides
```

Нужен только Python 3 — без зависимостей.

## Переснять скриншоты (интерфейс изменился)

1. Поднять приложение на **чистой** базе в dev-режиме почты:

   ```bash
   cd signal-monitor
   HOST=127.0.0.1 PORT=5175 DATA_DIR=/tmp/sm-demo APP_URL=http://localhost:5175 node server/index.js
   ```

2. Наполнить демо-данными (нужен `playwright` в `node_modules` или глобально —
   `npm i -D playwright && npx playwright install chromium`):

   ```bash
   node tools/seed.mjs
   ```

3. Остановить сервер, состарить сигналы и запустить снова:

   ```bash
   python3 tools/backdate.py /tmp/sm-demo/signal-monitor.db
   node server/index.js   # с теми же переменными
   ```

   Фоновый процесс сам переведет сигнал «Блок А, кровля» (72 ч) в Красный.

4. Снять экраны и сжать:

   ```bash
   node tools/shoot.mjs
   python3 tools/webp.py
   python3 build_all.py
   ```

Демо-учетные записи, которые заводит `seed.mjs`: `admin/admin123` (главный),
`petrov/petrov123` (администратор, Проектирование + Поставка),
`sidorova/sidorova123` (руководитель, Проектирование),
`kuznetsov/kuznetsov123` (руководитель, Поставка + Разное),
подрядчики `ООО «СтройМонтаж»/stroy123` и `АО «ЭнергоСеть»/energo123`.

## Как устроен build.py

- `page(role, title, description, hero, toc, sections, links)` — оболочка: шапка,
  hero, липкое оглавление, подвал с перекрестными ссылками.
- `section(n, id, title, lead, body, dev=False)` — раздел с номером; `dev=True`
  помечает разделы «для разработчика».
- `shot(name, url, who, cap)` — скриншот в рамке браузера; `shots_mobile([...])` —
  телефонные кадры рядом.
- `scenario(title, steps)` — пошаговый проигрыватель; шаг — `dict(t, d, img, text)`.
- `table`, `matrix` (таблица прав с анимированными отметками), `defs`, `zones`,
  `yes_no`, `note`, `menu`, `endpoints`, `fsm()` (схема статусов), `clock(text)`.
- Повторные вхождения одного скриншота не дублируют base64: первое несет данные
  (`data-key`), остальные помечены `data-img`, и скрипт копирует `src`.

Цвет роли задается атрибутом `data-role` на `<html>` (`superadmin` — янтарный,
`admin` — синий, `contractor` — зеленый); темы переключаются `data-theme`
или системной настройкой.
